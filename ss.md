# Отчет по лабораторной работе №2: Работа с Git

## Цель работы
Изучение основ работы с системой контроля версий Git, создание локальных и удаленных репозиториев, управление изменениями, ветвление и разрешение конфликтов слияния.

## Выполнение работы

### 4.2.1-4.2.2 Инициализация репозитория и первые коммиты
Была создана директория `repo_new` и инициализирован новый Git-репозиторий.  
Создан файл `file.txt` и пустая директория `empty/` (с файлом `.gitkeep` для отслеживания Git).

Команды:
```powershell
mkdir repo_new
cd repo_new
git init
git add .
git commit -m "First commit"
```

### 4.2.3 Создание удаленного репозитория
Был создан "голый" (bare) репозиторий `repo_master` для имитации удаленного сервера.  
В локальном репозитории `repo_new` был добавлен удаленный адрес `origin` и выполнена первая выгрузка (push) ветки `master`.

Команды:
```powershell
mkdir repo_master
cd repo_master
git init --bare
cd ../repo_new
git remote add origin "../repo_master"
git push --set-upstream origin master
```

### 4.2.5 Клонирование репозитория
Репозиторий `repo_master` был клонирован в новую директорию `repo_cloned`.

Команды:
```powershell
git clone "./repo_master" "repo_cloned"
```

### 4.2.6 Работа с конфликтами слияния
1. В репозитории `repo_cloned` был изменен файл `file.txt`, изменения были зафиксированы и отправлены в `repo_master`.
2. В репозитории `repo_new` также был изменен тот же файл `file.txt` (другая строка или та же самая), что при попытке `git push` вызвало ошибку, так как удаленная ветка ушла вперед.
3. При выполнении `git pull` в `repo_new` возник конфликт слияния.
4. Конфликт был разрешен вручную путем объединения изменений.
5. Результат был зафиксирован и успешно отправлен в удаленный репозиторий.

Лог коммитов после разрешения конфликта:
```
90c3fb4 Merged
0a46ee5 other second
e096b22 second
c4e1dc4 First commit
```
